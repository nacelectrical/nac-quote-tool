02 Defects found and fixed

Ten, in the order they were found. Four were mine, introduced during this work — they are marked, because a report that only lists other people's mistakes is not worth reading.

The quote tool showed a blank page to anyone not signed in
MINE — P3
The sign-in gate hid the whole document, and the sign-in form lives inside that document. Opening index.html or admin.html gave a blank page — no form, no message, no way in. It was live on the branch for four commits. The worst defect in this round, and it was found by chasing a page health check that reported "0 characters" rather than writing it off.
A static pressure check that never happened looked like one that passed
EXISTING
The engine never invented a figure, but nothing said the comparison had not been made and nothing stopped approval. For 85 of 120 models that is a false pass.
A three-phase unit could be quoted with no mention of the supply
EXISTING
Found by running your brochure plan. On a single-phase house that is a supply upgrade discovered on installation day and never quoted. The Equipment tab now asks what the site has; unconfirmed ranks single-phase units first, and a site recorded as single-phase makes it critical.
The PDF font width table was misread, so text would overflow the page
MINE — P6
Parsed on a four-character stride while @ is 1015 — four digits — so every width after it was read from the wrong offset. Customer documents would have had text running off the edge. There is now a test asserting the published Helvetica widths and that no wrapped line can exceed its column.
ServiceM8 answering 200 with no record id was reported as a created job
EXISTING
That is a job nobody can find. It is a failure now, with what ServiceM8 actually said. The job is also read back afterwards, which is both the confirmation and where the job number comes from.
When a ServiceM8 job failed to create, nobody found out
EXISTING
sign.html fired the request and dropped the result. Not the customer's problem — but it was not reaching you either. The outcome is written onto the quote row server-side now, where a closed tab cannot lose it.
Five browser tests were hanging forever, silently
MINE — P3
The sign-in gate broke them and they simply never finished, which is exactly what a real user would have experienced. Fixed, and auth-gate.mjs now checks the gate is on screen rather than merely present in the DOM — present-but-invisible was the whole of the blank page defect above, and the old assertion could not tell the difference.
CUP'D was counted as conditioned floor area
EXISTING
It is a cupboard. On your brochure plan it carries no size so it changed nothing, but on a plan where it does it would have gone straight into the load. CUP'D, CUPB, CPD, CUPBOARD, broom and cloak are all excluded now.
A second design at the same site interrupted the estimator on every save
MINE — P7
"Ducted install" then "Add a second system" is one job described two ways. The record keeps the first wording and nobody is asked about it.
A customer's second property was reported as a data entry error
MINE — P7
The address on a design is the site address, not the customer's own. It belongs to the job, where it always did.

04 What is still not right

Limitations that remain after this round. None is a bug; all of them shape what the tool can tell you.

  • 85 of 120 models have no manufacturer static pressure on file. Braemar, Gree, Midea, Mitsubishi Electric, Mitsubishi Heavy and Samsung have none at all. Designs on those models cannot complete the static check until the figure is typed in from the data sheet. The full list is in docs/static-pressure-audit.txt.
  • 58 of 120 models have no supplier cost, so they cannot be costed or quoted without one being entered.
  • 25 of 52 material lines are shipped placeholder rates, not NAC prices. On cost-plus-fee they go straight through to the customer.
  • Plan reading by AI was never exercised here — the AI endpoints are unreachable from this environment. The deterministic engines behind them were tested instead, which is the half that must be right every time.
  • Row-level security is unproven until it is applied. Until then the sign-in screen is a door with no lock behind it.
  • There is one staff tier. Any authenticated user is treated as NAC staff. No second tier was invented because none was asked for.
  • No load or performance testing has been done at any point.

05 The five blockers, in order

Each one depends on the one before it. None needs a developer, and none takes long.

  1. Apply the security policies
    Run designer/rls.sql in the Supabase SQL editor. Until this is done the anon key that ships in the page source can still read every customer, every price and every design, whatever the sign-in screen says. The file explains each policy and carries its own undo block.
    Proves: an unauthenticated visitor gets nothing. Customer signing pages keep working.
  2. Prove the database really persists
    Open /db-selftest.html on the deployed app, signed in, and run it. It creates, reads back, updates, lists and deletes real rows in nac_settings, nac_quotes and nac_designs, and checks a whole design survives with its rooms, equipment, materials, pricing and revisions. Test rows are prefixed ZZ-SELFTEST- and deleted afterwards. Then sign out and run it again — the results should differ, and that difference is step 1 working.
    Turns P1 from NOT TESTABLE into a real answer. Do not skip the signed-out run.
  3. Set the 25 material rates
    HVAC Design Settings → Material rates. Run node tools/material-price-report.mjs for the list, or read it off the Materials tab where every placeholder is marked. Flexible duct, diffusers, dampers, grilles, cable, isolators and sundries are the bulk of it.
    Until then every quote carries a confirmation naming the guessed dollars.
  4. Create the customer and job records
    Run designer/crm-schema.sql — additive, no drops, no renames — then open /crm-migrate.html and press DRY RUN. Read what it says it would do, especially the disagreements it found, before pressing APPLY. Nothing is written until you do, nothing you already have is overwritten, and running it twice changes nothing the second time.
    Existing quotes, designs and the signing page are unaffected either way.
  5. Connect ServiceM8
    Set SERVICEM8_API_KEY in the Vercel project, then open /api/servicem8-selftest. It creates nothing — it reports whether the key is accepted, whether the records a job needs can be read, and whether failures can be recorded. Then accept one real quote and check the job appears.
    Turns P8 from NOT TESTABLE into a real answer.
When all five are done, the answer at the top of this page changes on evidence rather than on optimism. Until then the honest position is that the application behaves correctly against everything that could be tested here, and four of the eight priorities depend on systems this environment was never able to reach.
